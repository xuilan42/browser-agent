# Browser Agent

Chrome-расширение (Manifest V3) без сборки и зависимостей. Чат с LLM-агентом живёт в боковой панели Chrome рядом со страницей. Агент видит текущую вкладку (текст и скриншот), сам кликает, вводит текст и листает страницу, проверяя результат каждого шага, а ещё ищет в интернете и читает внешние страницы. Работает с любым внешним LLM API. Нужен Chrome 114+ (боковая панель).

## Установка

1. Открой `chrome://extensions` и включи режим разработчика.
2. Нажми «Загрузить распакованное» и выбери папку проекта.
3. Нажми иконку расширения — справа откроется боковая панель с чатом.
4. Панель не закрывается при переключении вкладок и работает с той вкладкой, что активна в её окне. На системных страницах (`chrome://…`, Chrome Web Store) агент страницу не видит, но чат и веб-поиск доступны.

Затем укажи API-ключ в настройках (шестерёнка в панели).

## Возможности

- **Агент «видит» страницу.** Перед запросом и после каждого шага он получает текстовый снимок (заголовки, текст, ссылки, формы, интерактивные элементы с `ref` вроде `e1`, `e2`; элементы на экране идут первыми, с координатами центра) и скриншот видимой области. Пункты раскрытых выпадающих списков, автодополнения и меню (`role="option"`/`menuitem`, кастомные dropdown'ы) тоже попадают в снимок, помечаются «(пункт выпадающего списка)» и показываются в приоритете. На скриншоте поверх элементов нарисованы цветные рамки с подписью `ref` (set-of-marks), поэтому модель сопоставляет картинку с нужным элементом. В контексте всегда лежит только последний скриншот и последний снимок, старые вычищаются. Значения полей паролей в снимок не попадают.
- **Работает со страницей, а не только отвечает.** Цикл «посмотрел → сделал → проверил по новому скриншоту → продолжил» идёт до выполнения задачи, максимум шагов задаётся в настройках (по умолчанию 15). Ход виден в чате: у ответа отображается лента шагов.
  - Действия: `click` (по `ref`, тексту, селектору или координатам `x,y`), `type`, `press` (Enter отправляет форму), `select`, `hover`, `scroll` (в том числе во внутренних прокручиваемых блоках), `wait`, `look` (обновить снимок и скриншот).
  - Если действие повторяется без результата, агент получает подсказку сменить подход.
- **Правка страницы (`edit_dom`).** Агент может менять DOM открытой вкладки: текст, атрибуты, стиль, `innerHTML`, вставлять и удалять элементы (по `ref` или селектору). Правки живут только в этой вкладке и пропадают при перезагрузке — исходник сайта не меняется. Произвольный JS не выполняется: `<script>` и `on*`-обработчики из вставляемого HTML вырезаются, `javascript:`-ссылки отклоняются. Разрушительные операции (удаление элемента, замена `innerHTML`) требуют подтверждения в панели.
- **Постоянные элементы (`persist_add` / `persist_list` / `persist_remove`).** Обычные правки (`edit_dom`, `eval_js`) пропадают после перезагрузки. Постоянные вставки сохраняются в расширении (`chrome.storage.local`) и восстанавливаются при каждой загрузке страницы отдельным content script (`content/persist.js`), который ждёт появления нужного контейнера через `MutationObserver` (работает и на SPA). Scope выбирается: `url` — только эта страница, `origin` — весь домен; агент выбирает его по смыслу просьбы. Вставляемый HTML санируется (без `<script>`/`on*`/`javascript:`), поэтому постоянная вставка не становится вечным скриптом. Сохранённые элементы для текущей вкладки видны в панели (кнопка-закладка в шапке) и удаляются оттуда или через `persist_remove`.
- **Выполнение JS (`eval_js`, по умолчанию выключено).** Если включить галочку в настройках, агент получает самый мощный инструмент — выполнение произвольного JavaScript в контексте вкладки с возвратом результата (`await` поддерживается). Через него доступно практически всё, что умеет браузерный JS на странице: DOM и стили, события и клики, `fetch`/XHR, `localStorage`/`sessionStorage`, `cookie`, `history`, `window`, сбор данных и т.д. Выполняется в `MAIN`-мире (видны переменные страницы), а если её CSP заблокирует `new Function` — автоматически повторяется в изолированном мире расширения (CSP страницы там не действует, доступен весь DOM). По умолчанию выключено; при включённом «Подтверждении опасных действий» каждый вызов спрашивает разрешение в панели (это подтверждение можно отключить отдельной галочкой).
- **Рисование поверх страницы (just for fun).** На прозрачном холсте поверх сайта можно рисовать: кисть, линия, прямоугольник, текст, ластик, выбор цвета и толщины, очистка и сохранение в PNG.
  - Вручную: кнопка-карандаш в шапке панели включает режим — рисуешь мышью, `Esc` выключает.
  - Агентом: есть инструмент `draw` (операции `stroke`/`line`/`rect`/`text`/`clear`). В промпте агенту сказано рисовать только по явной просьбе («обведи кнопку», «пририсуй усы»), иначе он не рисует. Холст — это слой поверх страницы, саму страницу он не меняет.
- **Несколько вкладок.** Агент работает не только с одной вкладкой: `list_tabs` показывает вкладки окна, `switch_tab` делает нужную рабочей (действия и снимок переключаются на неё; можно работать в фоне, не мешая пользователю), `close_tab` закрывает, `open_url` с `newTab` открывает новую и делает её рабочей. Так можно открыть несколько страниц и обойти их по очереди.
- **Интернет.** `web_search` ищет через Wikipedia (ru/en), DuckDuckGo Instant Answer и, если результатов мало, через фоновую вкладку (DuckDuckGo HTML, затем Bing). `fetch_url` читает текст страницы, `open_url` открывает адрес в текущей или новой вкладке.
- **Сетевой терминал (`net_cmd`).** Настоящего shell/ICMP из браузера нет (песочница Chrome), но есть сетевые команды поверх HTTP: `http` — запрос как `curl` (метод, заголовки, тело → статус, заголовки, тело); `ping` — HTTP-доступность и время ответа (не ICMP); `headers` — только заголовки ответа; `dns` — резолв имени через публичный DoH-резолвер (`type=A/AAAA` даёт IP); `subdomains` — поддомены домена из публичных логов Certificate Transparency (`crt.sh`, пассивный источник — только то, на что выдавались сертификаты, не полный список и не брутфорс). Системные `ping`/`curl`/`nslookup` и доступ к ОС по-прежнему недоступны.
- **Tool calls.** Для `openai-compatible` используются нативные tool calls. Если провайдер их не поддерживает, а также для Anthropic, модель выводит блоки ```` ```action {...} ```` и расширение разбирает их из текста.
- **Модели без vision.** Если API отвергает изображения, агент сам отказывается от скриншотов и продолжает работать по тексту страницы, а этой модели в текущей сессии скриншоты больше не отправляются. Заранее отключить можно галочкой в настройках.
- **Чат.** Стриминг ответов, Markdown, остановка генерации кнопкой ■, история (последние 200 сообщений), перетаскиваемое окно, светлая и тёмная тема.

## Настройки

| Поле | Описание |
|------|----------|
| Провайдер | `OpenAI-compatible` или `Anthropic` |
| Base URL | endpoint API |
| API Key | ключ (для localhost можно пустым) |
| Model | id модели; кнопка «Модели» подтягивает список |
| Custom headers | JSON с дополнительными заголовками (OpenRouter и т. п.) |
| System prompt | системная инструкция агента |
| Макс. шагов агента | сколько циклов «посмотрел → сделал» разрешено за один запрос (1–60, по умолчанию 15) |
| Streaming / timeout / temperature / top_p / max tokens | параметры генерации |
| Галочки у Temperature и Top P | отправлять ли эти параметры в запрос — сними, если модель их не принимает (o-серия OpenAI и т. п.) |
| Контекст страницы / скриншот | что отправлять модели вместе с вопросом; скриншот нужен vision-модели |
| Действия на странице / веб-поиск | включают и выключают соответствующие инструменты |
| Выполнение JS (eval_js) | ⚠️ даёт агенту инструмент запуска произвольного JS на странице; по умолчанию выключено |
| Автономный режим | 🤖 агент действует без подтверждений; доступен только при включённом «Выполнение JS» |
| Подтверждение опасных действий | перед кликом по кнопкам оплаты, удаления, отправки формы показывается запрос на подтверждение |
| Макс. символов контекста | лимит снимка страницы |
| Тема | светлая, тёмная или как в системе |

Пресеты: OpenAI, OpenRouter, Anthropic, Ollama, LM Studio.

Замечания:

- API-ключ хранится в `chrome.storage.local` и не синхронизируется через аккаунт Google. Остальные настройки лежат в `chrome.storage.sync`. Ключ, сохранённый старой версией в `sync`, переносится в `local` автоматически.
- `temperature` и `top_p` можно по отдельности отключить галочкой рядом с полем — тогда параметр не уходит в запрос. Это нужно для моделей, которые их не принимают (например, o-серия OpenAI). Если модель всё же вернёт ошибку 400 про эти параметры, расширение само уберёт их и повторит запрос.
- Для Anthropic, если включены оба, отправляется только `temperature` — новые модели Claude не принимают оба сразу.
- Скриншот уменьшается до 1280 px по ширине (JPEG), чтобы тратить меньше токенов. Чтобы модель реально «видела» страницу, нужна vision-модель, например `gpt-4o`, Claude или `llava` в Ollama.

## Безопасность

Расширению нужны права `tabs`, `scripting` и доступ ко всем `http(s)`-сайтам: так агент читает страницы и действует на них. Текст страниц и результаты поиска попадают в контекст модели, поэтому на недоверенных сайтах возможна prompt injection. Перед кликом по кнопкам, похожим на оплату, удаление или отправку формы, расширение спрашивает подтверждение (настройку можно отключить). Это эвристика по тексту кнопки, а не полная защита, поэтому не давай агенту доступ к страницам с чувствительными операциями без присмотра.

## Структура

```
manifest.json            — манифест MV3
background/
  service-worker.js      — открытие боковой панели, контекст вкладки, действия, поиск, открытие URL
content/
  extract.js             — снимок страницы с ref-идентификаторами и рисование меток на скриншоте (инжектится по запросу)
  actions.js             — выполнение действий на странице (инжектится по запросу)
  draw.js                — рисование поверх сайта: canvas-оверлей + панель инструментов (инжектится по запросу)
  persist.js             — постоянный content script: восстанавливает сохранённые элементы при каждой загрузке
panel/                   — UI чата в боковой панели Chrome
options/                 — страница настроек
lib/
  agent.js               — цикл агента: сообщения, скриншоты, tool calls, обновление контекста
  tools.js               — описание инструментов, system-подсказки, разбор action-блоков
  api.js                 — провайдеры OpenAI-compatible / Anthropic, SSE, список моделей, валидация
  page.js                — форматирование снимка страницы для LLM
  search.js              — веб-поиск и чтение URL
  storage.js             — настройки (sync), ключ API (local) и история
  markdown.js            — безопасный Markdown → HTML
  theme.js               — применение темы по id (system/light/dark/своя), инжект переменных
  themes.js              — реестр тем: встроенные + пользовательские (storage), CSS-переменные
```
